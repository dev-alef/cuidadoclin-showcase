# Decisões do produto

| Decisão | Motivo e consequência |
| --- | --- |
| CuidadoClin como nome de trabalho | Identidade própria; domínio adiado, sem alegação de registro de marca |
| Odontologia primeiro | Aproveitar os fluxos existentes antes de ampliar especialidades |
| Um produto, várias clínicas | Código compartilhado e dados autorizados por organização |
| Papéis por vínculo | Uma pessoa pode ter responsabilidades diferentes em clínicas diferentes |
| Administração sem acesso clínico automático | Acesso de dentista exige aprovação profissional assistida |
| Migração sem recifrar dados | Preservar chave, senha, identificadores e histórico do legado |
| Modelo pessoal exclusivo | Preservar a personalização original sem utilizá-la em nome de outro profissional |
| Convites e onboarding assistidos | Operação inicial controlada, sem cadastro aberto ou cobrança nesta etapa |
| Código privado, showcase separado | Apresentação pública com imagens e conteúdo fictícios |

Revogação e convites antigos não podem restaurar acesso indevido. O último administrador ativo é protegido também sob concorrência. Essas regras são verificadas no servidor e em transações.

O operador aprova acesso clínico e publica modelos; essa função não concede acesso clínico global ao produto. E-mail automático só é anunciado quando existe transporte configurado, com validação real pendente antes de onboarding externo.
